# Postmortem: PDF spec uploads failed for one day (fictional, for training)

## Summary
After the product API moved behind ingress-nginx, every PDF spec upload larger than 1 MB failed with HTTP 413. Small uploads worked, so the problem was not noticed in testing.

## Impact
Product managers could not attach specification sheets for about one working day. No data was lost.

## Timeline (UTC+8)
- 09:10 New Ingress deployed for `platform.local`.
- 11:30 First user report: "upload says Request Entity Too Large".
- 15:45 Root cause found by comparing the nginx HTML error with the API's JSON errors.
- 16:05 Annotation added and re-applied; uploads working.

## Root cause
ingress-nginx defaults to a 1 MB request body limit. The Ingress manifest did not set `nginx.ingress.kubernetes.io/proxy-body-size`. The API's own limit (20 MB) was never reached.

## Resolution
Added `proxy-body-size: "25m"` to `platform-eng-ingress` and `40m` to `lab4-ai-ingress` for base64 uploads through MCP.
